# 02 — Reading the Home `.MDL` model (what the converter needs)

The converter only needs **triangles in world space** plus enough material information to decide which meshes to
leave out (glows, glass, foliage). This document covers exactly that part of the HM model format (versions
0x0101–0x0104). The layout comes from the kit's HMCore reader (`mdlb/src/00.js`), which our Python pipeline runs
unchanged through node; `MdlReader.cs` is a straight port of the reading half.

## 1. Basics

* **Big-endian** throughout.
* **Relative pointers**: a pointer field holds a signed 32-bit offset **relative to the field's own position**.
  `target = fieldOffset + value`; 0 means null.
* Names are **hashes**, not strings: `hash(name) = ~crc32(latin1(name))` (standard zlib CRC-32, then bitwise NOT).
  Useful known hashes (compute them, do not hard-code): `IN.position`, `IN.normal`, `IN.texCoord`, `IN.tangent`,
  `default`, `emissive`, `blend`, `colourMap`, `normalMap`, `specularMap`, `emissiveMap`, `envMap`.
* Vertex positions are already in **Home world space, metres, Y up** — the same frame as the HKX and the `.SCENE` file.
  The scene places the model with an identity transform, so no conversion is needed.

## 2. File header

| Offset | Size | Meaning |
|---|---|---|
| 0x00 | 2 | `'H' 'M'` |
| 0x02 | u16 | version 0x0101…0x0104 |
| 0x04 | u32 | skeleton (0 for environments) |
| 0x08 | u32 | (unknown, keep) |
| 0x0C | u32 | mesh count |
| 0x10 | rel | mesh table (76-byte records) |
| 0x14 | u32 | material count |
| 0x18 | rel | material table (72-byte records) |
| 0x1C | rel | model bounding sphere (4 floats), may be null |
| 0x24 | rel | end of file marker |

## 3. Mesh record (76 bytes)

| Offset | Type | Meaning |
|---|---|---|
| +0 | u32 | mesh name hash |
| +4 | u32 | primitive: **5 = triangle list**, **6 = triangle strip** |
| +8 | u32 | index count |
| +12 | rel | indices (u16 each) |
| +16 | u32 | vertex count |
| +20 | u32 | vertex stride in bytes |
| +24 | rel | vertex data (`count × stride` bytes) |
| +28 | u32 | number of vertex fields |
| +32 | rel | field table (8 bytes per field) |
| +36 | rel | material: points at a record in the material table → `index = (target − materialTable) / 72` |
| +40, +44, +48, +64, +68, +72 | | skinning / blend shapes / cloth — non-zero means skinned; environments have 0 |
| +52 | u32 | flags |
| +56 | rel | mesh bounding sphere |
| +60, +62 | u16 | (unknown) |

**Vertex field** (8 bytes): `u32 nameHash, u8 offset, u8 type, u8 count, u8 normalised`.
Types: 1 short-norm (2 B), 2 **float** (4 B), 3 half (2 B), 4 ubyte-norm, 5 short, 6 packed (4 B), 7 ubyte.

**Position field**: the field whose name hash is `hash("IN.position")`; if none matches, the first field with
`type == 2 (float)` and `count == 3`. Position of vertex `i` = three big-endian floats at
`vertexData + i × stride + field.offset`.

## 4. Turning indices into triangles

* **List (5)**: every 3 indices `a b c`; skip if any two are equal.
* **Strip (6)**: for `k = 0 … n−3`, take `a=idx[k], b=idx[k+1], c=idx[k+2]`; skip degenerate ones (any two equal —
  that is how strips are joined); for odd `k` swap the first two (`b a c`) to keep the winding consistent.

Winding does not matter for collision (we voxelise surfaces), but keeping it right costs nothing.

## 5. Material record (72 bytes) — the bits the filter uses

| Offset | Type | Meaning |
|---|---|---|
| +0 | rel | source file string |
| +4 | u32 | **material type hash** — `hash("emissive")` for glows; Sony glass uses type **0x7F05531A**; baked/default lit uses e.g. 0x863560FD |
| +8 | u32 | material instance name hash |
| +12 | u32 | constant count |
| +16 / +20 | rel | constant name hashes / float4 values |
| +24 | u32 | texture count |
| +28 | rel | texture slot hashes (u32 each) |
| +32 | rel | texture records (24 bytes each: rel filename, u32 wrap bits, u32 border colour, f32 lodMin, lodMax, lodBias) |
| +36 | u32 | flags |
| +40 / +42 | u16 | blend src / dst |
| +44 | u32 | alpha function |
| +48 | f32 | alpha reference |
| +52 | rel | extra parameters (count + hash/value pairs) |
| +56 | 16 B | reserved |

Texture file names are Windows paths (`...\TEXTURES\PALM_LEAF_C.DDS`); the filter looks at the part after the last `\`.

## 6. What the converter extracts per mesh

```
index, nameHash, materialIndex, materialTypeHash, materialInstanceHash, alphaFunc, flags,
textures: [(slotHash, fileName)], triangleCount, triangles (world xyz × 3)
```

`mdl_dump.js` writes this as `prefix.json` + a flat float32 file of all triangles (`prefix.bin`, 9 floats per triangle),
which is what the Python reference consumes.

## 7. Notes from the models we tested

* Basic Apartment: 70 meshes, 18,601 triangles, all plain float positions, list and strip primitives mixed.
* Stilt house (generated by us): 742k triangles. Every material had the same `alphaFunc` (516), so alpha settings
  **cannot** be used to find foliage — use texture names.
* Glow cards, light shafts and similar are `emissive` and should not collide (skipped by default).
* Glass (`0x7F05531A`) *should* collide in most spaces (windows, balcony glass) — it is kept by default.
